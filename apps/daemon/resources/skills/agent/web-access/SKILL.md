# web-access 技能

## 浏览哲学

**像人一样思考，兼顾高效与适应性地完成任务。** 带着目标进入，边看边判断，遇到阻碍就解决，发现内容不够就深入——全程围绕「我要达成什么」做决策。

**① 明确成功标准** — 先定义什么算完成：需要获取什么信息、执行什么操作、达到什么结果？这是后续所有判断的锚点。

**② 选择起点** — 根据任务性质与平台特征，选最可能直达的方式作为第一步去验证：已知 URL 且静态可达 → web_fetch；只需发现来源 → web_search；需要登录态/交互/已知静态层无效的平台（小红书、微信公众号等）→ 直接 browser。

**③ 过程校验** — 每一步的结果都是证据，不只是成败二元信号。用结果对照成功标准更新判断：搜索多次没有质的改进就换更根本的方式（定位一手来源）；API 报错、页面缺预期元素、重试无改善，都是在告诉你重新评估方向，不在同一个方式上反复重试。遇到弹窗、登录墙，先判断它是否真的挡住了目标——内容可能已在 DOM 中，交互只是展示手段。

**④ 达标即停** — 对照成功标准确认完成后才停止；也不过度操作，不为了「完整」浪费代价。

## 工具选择

| 场景 | 工具 |
|------|------|
| 发现信息来源（关键词搜索、摘要列表） | **web_search** |
| URL 已知，读取页面正文 | **web_fetch**（默认 markdown 省 token；`format=html` 拿原始 HTML——meta、JSON-LD 等结构化字段） |
| 需要登录态、交互操作、动态渲染内容、已知反爬/静态层无效的站点 | **browser**（单工具 + action 分发） |
| 搜索引擎全部挂掉时的兜底 | browser `action=open` 开搜索引擎结果页，`action=eval` 提取结果 |

browser 不要求 URL 已知——可从任意入口出发，通过页面内搜索、点击、跳转找到目标内容。action 一览：`open`（新开 tab）/ `navigate` / `back` / `eval`（执行 JS，读写 DOM、提取数据）/ `click` / `click_at`（真实鼠标手势，可触发文件对话框）/ `set_files`（文件上传）/ `scroll` / `screenshot` / `status` / `close`。

进入 browser 层后，eval 就是你的眼睛和手：先 `action=eval` 了解页面结构（有什么链接、按钮、表单、文本），再决定下一步动作，不需要提前规划所有步骤。

## 页面就绪契约

`open` / `navigate` 返回，只代表浏览器完成了当前文档的基础加载，**不代表目标内容已经出现**。HTTP 200、导航调用成功，都不能单独作为任务完成标准。

导航后先用 `action=eval` 检查目标内容。若目标内容尚未出现，而页面仍是空白、加载态、验证页、登录跳转或其它可能继续变化的中间状态，在默认 **15 秒观察窗**内持续观察 URL、标题和 DOM；页面发生跳转或内容变化后重新判断。只有目标内容已获取，或观察窗结束后仍存在明确阻碍，才能继续提取或报告失败。

## 登录判断

browser 连接的是用户日常浏览器，天然携带登录态。登录判断的核心问题只有一个：**目标内容拿到了吗？**

打开页面后先尝试获取目标内容。只有当确认目标内容无法获取、且判断登录能解决时，才告知用户：「当前页面在未登录状态下无法获取[具体内容]，请在你的浏览器中登录 [网站名]，完成后告诉我继续。」用户登录完成后无需重启任何东西，刷新页面继续。

## 技术事实

- **eval 穿透边界**：DOM 中存在选择器不可跨越的边界（Shadow DOM 的 `shadowRoot`、iframe 的 `contentDocument`）；eval 递归遍历可一次穿透所有层级，适合快速了解未知页面的完整结构。
- **scroll 触发懒加载**：滚到底部会触发懒加载，未进入视口的图片/内容在滚动前可能尚未加载——提取前先滚动。
- **站点内链接自带完整参数**：通过页面内可交互单元（卡片、条目、按钮）自然到达的 URL 天然携带平台所需的完整上下文（token 等）；手动构造/裁剪参数的 URL 可能被拦截、返回错误页或触发反爬。
- **平台「内容不存在」「页面不见了」等提示不可尽信**：可能是访问方式问题（URL 缺失必要参数、触发反爬）而非内容本身不存在。
- **密集开页触发风控**：短时间内大量 `action=open` 可能触发网站反爬风控——批量任务控制节奏。
- **eval 返回值**：JS 对象需 `JSON.stringify` 序列化后返回，字符串/数字/布尔可直接返回。

## 程序化 vs GUI 交互

- **程序化方式**（构造 URL 直接 navigate、eval 操作 DOM）：成功时快、精确，但对网站来说不是正常用户行为，可能触发反爬。
- **GUI 交互**（click 点击、填写输入框、scroll 滚动）：GUI 是为人设计的，网站不限制正常 UI 操作，确定性最高，但步骤多、慢。

按对目标平台的了解灵活选择：GUI 交互也是程序化方式的有效探测——通过一次真实交互观察站点实际行为（URL 模式、必需参数、跳转逻辑），为程序化操作提供依据；程序化受阻时，GUI 是可靠兜底。

## 反爬风险须知

部分站点（尤其社交平台）对浏览器自动化操作检测严格，**存在账号封禁风险**。操作用户日常浏览器中的登录账号时：控制操作频率、避免批量抓取、优先只读；涉及高频或批量操作社交平台账号时，建议用户改用不常用的小号，并向用户明示风险后再继续。
