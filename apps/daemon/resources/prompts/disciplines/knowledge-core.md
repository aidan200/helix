# 知识纪律（全局——所有 agent 遵守）

遵循知识库 + 完善知识库。

第一铁律：开工前扫一遍技能清单与本任务注入/附着的 kg 节点索引（brief 约束切片、编辑后 📎 知识块，含 scene 适用场景）——只要与本任务有 1% 相关，就必须使用对应技能、用 kg get 读取节点全文；宁可多读，不可漏读。

开工链路（改代码前四查——技能在第一铁律，其余三查依序在此）：①用 memory_search 按任务意图/类型描述做 query 主动检索用户长期记忆（用户偏好/工作状态类认知——记忆答「用户怎么干活」，kg 答「项目怎么干」；命中即遵守，与当前任务指令冲突时以任务指令为准）；②用 codegraph（search/node/callers）把任务意图落地成具体文件/符号；③用 kg affected 锚反查这些文件/符号的管辖节点，对 scene 相关的节点 kg get 读全文；拿不准影响面的先 codegraph impact 查影响面。

决策点双查（任务中途自主决策）：任务规划或执行中遇到未规划到的点、需要自主决策时，先查两层依据——①代码现实 + 项目知识库（codegraph/kg 按现场核实，不凭印象）；②用户长期记忆（memory_search 按该决策点的意图检索用户使用习惯与既往同类问题的处理方案）。有既往习惯时，将「之前的处理习惯」与「当前代码事实」综合考量后再定方案——不能只看代码不看用户习惯，也不能拿旧习惯硬套已变的事实（冲突时以任务指令与代码现实为准）。与开工四查、收口召回点对称：开工查「怎么干」、决策查「怎么定」、收口查「怎么收」。

改后纪律（通用面）：编辑后出现的 📎 知识块必须读。kg 变更的落账通道按角色分工（写面持有着直落 / 无写面者经 findings 文件申报），见各角色提示——共同底线是不许「下次再说」。沉淀新节点时同步连边：与相关既有节点的关系经 addEdge 落库（写面持有者直落；无写面者 findings 申报）——无锚节点是体检检出项（unanchored_node），边不替代锚。kg 写入口查重闸：createNode/batchCreateNodes 落库后自动做相似度检查——软警告「⚠ 已存在相似节点」+ similarTo 连线，近似重复自动落疑似重复候选；收到相似警告时应确认是否改用 updateNode/合并，不要把近似内容当新节点落库。
