# 工程纪律（全局——所有 agent 遵守）

①并行开发一律隔离 worktree：并行执行多个开发工作时，各自在隔离 worktree 的分支上干活与提交，禁止共享同一工作树并行写；worktree 落点一律仓内 `<repo>/.worktrees/<slug>`（机械面经编排 spawn 的 isolated 写面档由 daemon 统一 provision；确需手建时也落此口径），禁止顶层兄弟目录（helix-wt-* 等形态）与 /tmp 落点；图谱产出型任务（kg-bootstrap/kg-review）不开 worktree，主工作树执行（kg 库是 SQLite 单写面，隔离副本各自写库合并必分叉）。任何执行者都不自行 merge——各分支的合入由 MainAgent 在计划阶段检查点统一执行（merge 冲突由 MainAgent 裁决解决）。临时文件/工具缓存/截图导出的缺省落点 = `<workspace>/.helix/tmp/`（落点规范批，2026-10-10——不落 ~/.helix、不落系统 /tmp）。落在 `.helix/tmp/` 的临时物料用后即删（清理纪律批，2026-10-21）：任务收口/会话善后时删除自己创建的截图导出、暂存与验证产物——只删自建，不动并发会话在用之物；确需跨任务留存的在收口交代中说明；`tool-cache/`（可再生缓存）与 `.worktrees/`（随 worktree 生命周期）不在此列。

②计划阶段检查 commit：推进/验收计划阶段时核查工作树提交情况，有未提交工作即要求先提交再推进；收尾前先提交——未提交的工作等于没做。收口记忆召回点（与「收尾前先提交」同刻衔接）：收口/向用户交代前，用 memory_search 按「收尾/善后/清理」意图检索一次用户习惯偏好（临时文件处置、现场恢复、文档落盘位置、交代方式等），命中即按偏好完成善后再收口；无命中即正常收口。收口锚对账点（与「收尾前先提交」同刻衔接）：收口/向用户交代前对本任务改动面做锚对账——改动文件 → kg affected 反查 → 锚健康检查（声明 vs 物化、orphan 状态）→ 机械项当场处置（高置信重挂经声明修正、定向 prune 死锚），残量（符号消亡后节点去留等需内容判断的）进收口报告直接交代用户，不留台账等体检。边界条款：凡涉及「节点内容还对不对」的（supersede/正文修订）仍走 findings→候选人审通道——内容人审边界与锚机械维护严格分开。

③文档落盘分三级，项目仓只收定稿：a. 过程性临时文档（任务 brief / evidence / 设计候选 / 验证记录）一律产出到 workspace 根（会话 cwd）的 `docs/` 下（如 `<workspace>/docs/temp/`），禁止写进项目仓；b. 项目仓 `docs/` 只落「确认即不可更改」的定稿文档（如 design-system 主题定稿）——记录实现逻辑/架构决策/演进史这类可被推翻更新的内容一律不落项目仓文档；c. 代码事实与架构知识一律进知识图谱（按各角色落账通道即时入账），不在文档里另记一套——文档与图谱双轨是已判过的反模式（v1 kg 体系与项目仓 ADR/hotfix 档均因此而退役）。
