### 17.14 管家流式体验批（additive 微批）

> V2.5 体验批：管家问答「终态一次性纯文本」→「边生成边显示 + Markdown 渲染」。
> **版本位不动（v0.13 微批，追加当前版本文件尾部——§40 分配规则）**。
>
> - **+1 事件**（steward 族）：`steward.ask.delta` —— steward.ask 的流式增量帧
>   （点对点发发起连接；仅文本生成段逐 chunk 下发，工具执行段静默不发）。
>   **语义 = 增量 delta + 前端聚合**（与主聊天 `chat.stream.delta` 同构，非累计
>   文本）：payload `{ delta: string; seq: number }`，delta 为本帧增量文本，
>   seq 为单次 ask 内单调顺序号（1 起；不携带 messageId——管家面板单飞在途
>   互斥，无多轮并发歧义）。终态仍发 `steward.ask.result`（权威文本 = answer
>   分支 text，前端以终态覆盖聚合缓冲；delta 不落盘不持久化，重连即弃）。
> - daemon 侧：StewardLlmPort.complete 加可选 onDelta 回调面（消息形状与工具面
>   不动——只加流式回调）；PiStewardLlmAdapter 透传 pi-ai streamSimple 的
>   text_delta chunk；StewardService.ask 在工具循环的文本生成段逐 chunk 发帧
>   （money gate 关闭 = 零 LLM 调用零 delta）。
> - shell 侧：useSteward 聚合 delta 到 streamingText（流式不落盘语义——messages
>   不追加，result 到达清空并落权威消息）；StewardPanel steward 气泡换
>   MarkdownMessage 渲染（user 气泡保持纯文本，与主聊天同口径）。
> - 兼容性：additive——旧 shell 对未知事件结构安全（LISTEN_SURFACE type 白名单
>   不命中即忽略；session dispatcher 未注册 type 保持原状态 no-op）。
> - **计数演进**：命令 87 不变；事件 104 → 105（catalog.test.ts 双向一致性
>   机械守护，代码自证）。
