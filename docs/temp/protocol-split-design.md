# PROTOCOL.md 现行/备案拆分设计（protocol-split）

> 状态：**待批设计**——用户裁决「坚持单一职责，把历史批次备案与现行契约分离」后产出的评估与设计方案。批准后按 §5 执行批次实施。

## 1. 背景与动机

`packages/protocol/PROTOCOL.md`（2778 行 / 164KB）是 WS 契约唯一事实源（SoT），同时承担两种职责：

1. **现行契约**：协议现在长什么样（§1–§9 基线、§15 命令全集、§16 事件全集、§17.1–17.4 SoT 守护口径）——受 sot-consistency.test.ts 五断言机械守护；
2. **批次备案**：协议怎么演进成这样（§10–§14 v0.1–v0.4 演进登记、§17.5–§17.11 v0.5–v0.11 批次登记、§18–§23 v0.11 后 additive 微批备案）——每版本批追加一节，只增不删。

两类内容混杂导致：定点读 §15/§16 需翻越 ~840 行历史；文件随每次批次膨胀；「现行口径」与「考古记录」无结构边界。拆分为双文件实现单一职责：**现行文件 = 规格与守护；备案文件 = 变更登记**。

## 3. 设计决策

### 3.1 文件命名：`PROTOCOL-CHANGELOG.md`（不叫 HISTORY）

批次备案是**持续追加的活文档**（含当前批 v0.11 的 §17.11 与未来的批内补登），CHANGELOG 语义准确（变更登记），HISTORY 暗示死档案会误导「不再更新」。同目录放置：`packages/protocol/PROTOCOL-CHANGELOG.md`——契约文档跟包走、同 commit、git diff 同 PR 可读。

### 3.2 拆分边界：批次备案**全量**迁移（含当前批 §17.11）

- **搬**：§10–§14 + §17.5–§17.11 + §18–§23——所有「批次登记/演进备案」性质内容，无论历史批还是当前批；
- **不搬**：§1–§9、§15、§16、§17.1–§17.4——描述「协议现在是什么形状 + 怎么守护」。

理由（为什么当前批也搬）：若 §17.11 留现行文件，每次版本 bump 都要「旧批登记搬家 + 断言改节号」，维护动作多一步且容易漏；全量迁移后纪律单一——**「版本 bump / additive 微批 = CHANGELOG 加批次节 + PROTOCOL.md §15/§16 落字段行（同 commit）」**，现行文件从此永不因批次膨胀。

### 3.3 节号策略：**保留原节号，不重排**

现行文件 §9 之后直接 §15、§17 收缩到 §17.4——跳号处放显式指针：

> `> §10–§14（v0.1–v0.4 演进登记）已迁 PROTOCOL-CHANGELOG.md（原节号保留）。`

理由：sot 断言的节边界正则（`/^## 15\. /m` 等）零改动；§15.x/§16.x/§17.1–17.4 的 50+ 处外部注释引用零改动；节号重排的收益（美观）远小于断言面与引用面的全量重写风险。

### 3.4 内部交叉引用：头部映射声明消化

PROTOCOL.md 头部（版本说明块后）加一段全局声明：

> 本文档中形如 `§10–§14`、`§17.5+`、`§18–§23` 的节号引用，均指 `PROTOCOL-CHANGELOG.md` 中的**原节号**（迁移时原样保留，未重排）。§15/§16 字段表「登记版本」列的节号引用同此口径。

§15/§16 字段表内 ~25 处 `（§14.3）`/`（§18）`/`§10.4` 等引用**逐字不动**。

### 3.5 断言面改造（最小）

1. `thinking.test.ts`：readFileSync 的 URL 由 `../../PROTOCOL.md` → `../../PROTOCOL-CHANGELOG.md`（1 处；正则 `### 17.11 v…批次登记` 不变——节号原样搬）；
2. sot-consistency.test.ts：零改动；
3. **新增轻量断言（建议）**：sot-consistency 加第⑥条「文件职责守护」——CHANGELOG 文件存在且非空 + PROTOCOL.md 内不出现 `^## (1[0-4]|1[89]|2[0-3])\. ` 与 `^### 17\.(5|6|7|8|9|10|11) ` 批次节标题（防止未来把批次备案又写回现行文件，单一职责机械兜底）。断言口径同步登记进 §17.3。

### 3.6 外部注释迁移（35 处）

机械替换：`PROTOCOL.md §(10|11|12|13|14|17\.11|18|19|20|21|22|23)` → `PROTOCOL-CHANGELOG.md §…`（节号不变）。注意边界：外部引用中 §17.x 仅有 §17.11 一种形态（已核对），无误伤面；`§9`/`§15.x`/`§16.x`/`§17.1–17.4` 引用不动。

### 3.7 顺手卫生（同批 doc-only）

- 头部 ：5-6「28 命令 / 48 事件」→「61 命令 / 78 事件」；
- §17.1 「27 命令 / 47 事件」→ 改为「以 §15/§16 计数声明行为准」（避免再添一个会漂移的计数快照）；
- §17.2 登记律补一句：批次备案同 commit 落 `PROTOCOL-CHANGELOG.md` 对应批次节（版本 bump = 新批次节；additive 微批 = 批内补登节）。
